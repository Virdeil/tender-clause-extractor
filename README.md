# 招标文件 AI 助手

> 一份 115 页的政府采购竞争性磋商文件 → 结构化条款 → 带页码的问答 → 能自己决定查什么的 Agent
>
> 全部手写，不依赖 LangChain / LlamaIndex 等 RAG 框架。

---

## 这个仓库解决什么问题

招标文件厚、条款散、漏一条就可能废标。这个项目做三件事：

| 能力 | 做法 | 效果 |
|---|---|---|
| **条款抽取** | 长文切分 + LLM 结构化输出 | 35 条无效条款，召回 100%，单条准确 96.4% |
| **带页码问答** | 手写 RAG（向量 + BM25 + RRF + Rerank） | 22 题：答案 100%，页码 95% |
| **自主检索** | Function Calling + 多轮工具调用 | 4 道多跳题：RAG 0/4 → Agent 4/4 |

**一句话：不是"调个 API"，是把检索、评测、成本、失效模式都量过一遍。**

## 快速开始

```bash
pip install requests jieba pypdf openpyxl streamlit

# 1) 设置 API Key（硅基流动）
#    Windows: setx SF_API_KEY "sk-xxx"   然后重开终端
#    macOS/Linux: export SF_API_KEY="sk-xxx"

# 2) 把招标文件按页导出为 txt，放到 招标文件分章节/ 目录
#    每个文件用 【PDF 第 N 页】 标记分页

# 3) 建索引（句子级，约 40 秒 / 115 页）
python 03_建索引.py

# 4a) 命令行问答
python 06_RAG问答.py

# 4b) 网页版（固定文件）
streamlit run 08_网页版.py

# 4c) 网页版（上传任意 PDF，现场建索引）
streamlit run 09_上传版.py

# 4d) Agent 版（模型自己决定查不查）
python 11_Agent.py
```

## 评测结果

### 1. 条款抽取（人工基线对照）

以手抄的 35 条为基准：**召回 100%**，单条准确率 **96.4%**（2 页文件 5 次）／ **100%**（18 页文件）。

> 起点是人工覆盖率约 50% —— 没有这把尺子，AI 漏了 9 条也发现不了。

### 2. 手写 RAG：五版迭代

| 版本 | 方案 | 答案 | 页码 |
|---|---|---|---|
| 平台版 | 可视化编排：整页切分 + 阈值 0 | 100% | 65% |
| v1 | 350 字块 + 余弦 + BM25 + RRF | 80% | 70% |
| v2 | + small-to-big（句子检索 → 整页生成） | 90% | 85% |
| v3 | + TopK 8 + 提示词加固 | 95.5% | 90% |
| **v4** | **+ Rerank 两阶段召回** | **100%** | **95%** |

**核心差异不在模型，在数据**：平台版的页码由模型"说"出来，手写版把页码写进切分元数据，模型只能原样复制。

### 3. 跨文件泛化（关键边界）

95% 是在"调过的文件"上测的。另取两份未见过的磋商文件：

| 文件 | 规模 | 引用支撑率 | 人工复核 |
|---|---|---|---|
| 原文件（调过） | 115 页 / 22 题 | 90% | — |
| 河北某工程 | 71 页 / 8 题 | 88% | 7/8 |
| 武汉东西湖 | 48 页 / 8 题 | 62% | 6/8 |
| **合计（新文件）** | **16 题** | **75%** | **81%** |

> **这 14 个百分点就是过拟合的量。**
> 失败集中在三类：术语不一致（磋商/投标有效期）、检索被合同附件带偏、"不收取"类否定表述。

### 4. RAG vs Agent：题型决定架构

| 题型 | RAG | Agent | 平均轮数 | 每题成本 |
|---|---|---|---|---|
| 22 题单点事实 | 20/20 | 20/20 | 1.00 → 2.27 | 0.0036 → 0.0037 元 |
| 4 题多跳推理 | **0/4** | **4/4** | 1.00 → 2.75 | 0.0010 → 0.0072 元 |
| 陷阱题拒答 | 2/2 | 2/2 | — | — |

**单点题上 Agent 一分钱没多花**（RAG 一次塞 3 整页，Agent 第一轮只塞问题，省下的和多出的抵消）。

**多跳题上 RAG 全错**——它只有一次检索机会，失败后要么拒答，要么硬凑：

> 问：获取采购文件的截止时间和提交响应文件的截止时间分别是？间隔几天？
>
> RAG 答：「2023 年 11 月 15 日 / 2023 年 12 月 5 日，间隔 20 天（依据第 1 页）」
>
> 实际是 2026-10-15 与 2026-10-26，间隔 11 天。
> **它检索到封面页，找不到就编了两个格式完美的假日期。**

## 六个关键工程决策

| # | 决策 | 为什么 |
|---|---|---|
| 1 | 页码写入切分元数据 | 平台不返回页码；让模型"生成"页码必然漂移 |
| 2 | 2-gram → jieba 分词 | 「需要具备」被切成「要具」等跨词组合，IDF 极高制造假匹配——实测把违约金条款顶到第 1 名 |
| 3 | 归一化加权 → RRF | 两种检索分数量纲不可比，一个离群值就能翻盘；RRF 只看排名 |
| 4 | 统一块 → small-to-big | 块大则主题混杂检索不准，块小则上下文不足答不全 |
| 5 | 加 Rerank 两阶段召回 | 双塔粗排快但粗、交互式精排准但慢；粗排 20 句 → 精排 5 句 |
| 6 | 加同义词表 + 否定式规则 | 换文件后「不收取保证金」被答成"未提及" |

### Agent 的三道护栏（缺一个就出事）

| 护栏 | 做法 | 不做的后果 |
|---|---|---|
| 预算上限 | 超预算时设 `tool_choice=none`，强制收尾 | 死循环烧钱（成本随轮数近平方增长） |
| 空回答兜底 | `content` 为空则推它一句"必须作答" | 静默失败：界面一片空白 |
| 工具输入约束 | 要求 2–4 个关键词，不带「本项目」等前缀 | 同一个问题它换个说法就检索不到 |

## 已知局限

这份代码诚实地记录了它做不到的事：

- **扫描件不支持**。PDF 提取不到文字时只会提示"需要 OCR"，不做 OCR 处理。
- **表格结构会丢**。PDF 表格转文本后变成流水文本，是当前最大的短板。
- **TXT 上传没有页码**。整篇按第 1 页处理，出处失去意义。
- **只验证过 3 份文件**。术语和模板差异会显著影响效果，泛化数据见上。
- **关键词判定会误判**。「未在文件中明确给出」这类表述，曾被错误判成"没答对"。
- **过拟合风险**。切分参数、提示词、测试集都是对着第一份文件调的。
